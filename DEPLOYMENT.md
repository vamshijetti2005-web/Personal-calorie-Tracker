# Render deployment

The repository includes a Render Blueprint that creates:

- one Docker web service containing the React production build and Spring Boot
- one managed PostgreSQL database
- generated JWT signing secret
- a secure prompt for the Gemini API key

The deployed browser and API share one origin, while the source code and runtime
communication remain separated through REST.

## Deploy

1. Merge the deployment PR into `develop`.
2. Create or sign in to a [Render](https://render.com) account.
3. Connect Render to the GitHub repository.
4. In the Render dashboard, choose **New → Blueprint**.
5. Select `Personal-calorie-Tracker` and branch `develop`.
6. Render detects the root `render.yaml`.
7. Enter `GEMINI_API_KEY` when prompted. Do not put it in Git.
8. Apply the Blueprint and wait for the database and web service to become
   healthy.
9. Open the generated `https://...onrender.com` URL.

Flyway runs automatically when the web service starts. The demo account is:

```text
Email: demo@nourish.local
Password: DemoPass123!
```

## Blueprint configuration

`render.yaml` uses:

| Variable | Source |
| --- | --- |
| `RENDER_DATABASE_URL` | Managed PostgreSQL internal connection string |
| `JWT_SECRET` | Generated by Render |
| `GEMINI_API_KEY` | Secret entered during Blueprint creation |
| `GEMINI_MODEL` | `gemini-3.5-flash` |
| `PORT` | Injected by Render |

`RenderDatabaseEnvironment` converts Render's PostgreSQL URI to JDBC settings
before Spring Boot starts. The Docker build compiles React first, embeds only
its production assets in the Spring Boot JAR, and runs the final container as a
non-root user.

## Updating

The Blueprint deploys from `develop`. Push/merge changes to that branch and use
Render's automatic deployment or **Manual Deploy → Deploy latest commit**.

## Operational notes

- Free services can sleep when idle, so the first request can take longer.
- Free database availability and retention are governed by Render's current
  plan terms; check them before relying on the deployment long-term.
- Use a dedicated Gemini key with a quota appropriate for a public demo.
- Rotate `JWT_SECRET` only when you intend to invalidate all active login tokens.
- Never expose `GEMINI_API_KEY`, database credentials, or `JWT_SECRET` in
  frontend environment variables.
